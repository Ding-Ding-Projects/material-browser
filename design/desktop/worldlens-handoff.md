## Action sounds

Add a local persisted “Action sounds” on/off setting in Notifications, with localized help and a user-initiated Preview. Default on for a new installation is acceptable for the requested experience, while explicit saved off must remain off. Use the existing settings model/controller so the setting participates in validation, history and export. If quiet-hours/reduced-stimulation preferences suppress noncritical feedback, apply them to sounds too; sound and narration remain independent controls.

The initial design proposed navigation/selection, open/close and short success/failure cues. The final implementation deliberately limits sound to meaningful settled success and failure outcomes, avoiding frequent selection and navigation sounds. Its local synthesized melodic envelopes last approximately 410 ms for success and 370 ms for failure, with a 500 ms overlap suppression window. This is an intentional deviation from the earlier 120–180 ms success and 100–160 ms failure proposal. Soft attack/release avoids clicks; gain and concurrent voices are bounded. No network assets, startup sound, hover sound, keystroke sound, navigation/open/close cue or repeating busy sound is included. Initialize audio only after a real user gesture, catch unavailable/suspended audio without breaking the action. Emit one cue per meaningful accepted action or actual settled result, not both child and bubbling parent events. Never announce success when a promise rejects, a chooser cancels or a request is merely queued. Turning off stops queued/current cues immediately. Preview uses the same bounded audio path. Sounds never replace visible status or accessible announcements, and no secret entered value influences a cue.

The implementation uses explicit settled notification/result boundaries rather than navigation or a document-wide click listener that cannot distinguish disabled controls or host failures. Inspect overlap with existing notification/narration delivery to avoid duplicate feedback. Verify mute persistence across reload, unavailable audio, quiet-hours suppression, cancellation and failure separately. Source and automated audio-graph checks do not establish physical listening or perceived sound quality; no listening verification is claimed here.
